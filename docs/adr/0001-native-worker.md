# 用原生 Worker 和持久任务所有权替代 Python 容器

AniBT 2 使用 Go 编译的 Linux 可执行文件，由 systemd 管理。任务、资源领取、业务凭证和 Telegram 发件箱由 SQLite 的同一事务维护；控制器独占 qB 调用，媒体分析逐样本保存进度。此方案增加了编译与显式状态迁移的工作，但取消了容器和解释器运行依赖，并让取消、领取失效与关机排空具有明确合同。MediaInfo 保留为受限的系统子进程。

发布身份、内容身份、成功媒体凭证与活跃任务分别存储。自动清理日志不会撤销永久去重；对源数据的修正只撤销尚未提交的准备结果。已提交的哈希先与 qB 状态对账，再决定是否采用源修正。

部署先验证配置、依赖和只读接口，再启动等待激活的进程。激活前失败时恢复二进制、有效配置、单元文件和数据库快照；激活后只允许保持数据库模式兼容、保留最新状态的回滚。跨模式回滚必须显式迁移状态，不能恢复旧快照后假定外部操作没有发生。
